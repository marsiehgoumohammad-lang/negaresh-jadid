## قوانین الزامی پروژه (خط قرمز — نقض ممنوع)

1. **شاخه کاری:** قبل از هر تغییری از آخرین `main` یک شاخه Review بساز:
   ```
   review/seo-phase1-leader-admin-letters-2026-11
   ```
   هیچ کار مستقیمی روی `main` انجام نشود. Merge و Deploy فقط با اجازه صریح کاربر.

2. **وضعیت Git:** قبل از ویرایش:
   ```
   git status --short
   git diff --stat
   git diff --name-status
   ```
   به فایل‌های غیرمرتبط در Working Tree دست نزن. تغییرات قبلی محافظت‌شده هستند.

3. **نیم‌فاصله:** در تمام فایل‌های ویرایش‌شده تعداد کاراکتر `\u200c` (ZWNJ) باید دقیقاً `0` باشد. از نیم‌فاصله استفاده نکن.

4. **URL و Slug:** هیچ URL، slug، canonical یا مسیر موجود را تغییر نده یا حذف نکن.

5. **صفحات برنده (Winners) — دست نزن:**
   - تمام صفحات خوشه وثیقه (`bail-substitution`, `bail-reduction`, `bail-to-surety`, `detention-to-bail`, `objection-to-criminal-security`, …)
   - `/samples/third-party-objection-to-execution`
   - `/samples/judgment-enforcement-grace-period`
   - `/samples/property-attachment-lifting-request`
   این صفحات فقط از طریق لینک‌سازی داخلی از صفحات این فاز تقویت می‌شوند؛ محتوا، عنوان، H1 و ساختار آن‌ها تغییر نکند.

6. **فایل‌های P0 محافظت‌شده:** به این فایل‌ها دست نزن:
   - `src/lib/calculators/legal-formulas.ts`
   - `src/components/calculators/DebtDelayCalculatorClient.tsx`
   - `src/components/calculators/DiyaCalculatorClient.tsx`
   - `src/app/api/samples/download/route.ts`
   - `src/components/samples/SampleLandingPageTemplate.tsx`

7. **صفحه با Impression بسیار بالا:**  
   `/samples/leader-office-letter` حدود ۱۲٬۵۰۰ Impression دارد. هر تغییر `metaTitle`، `metaDescription` یا `h1Title` باید حداقلی، داده‌محور و قابل برگشت باشد. اگر شک داری، فقط پیشنهاد بده و اعمال نکن.

8. **محتوا:** فارسی طبیعی و انسانی، دقیق از نظر اداری/حقوقی ایران، بدون تضمین نتیجه پرونده، بدون ادعاهای اثبات‌نشده، بدون معرفی سایت به‌عنوان سامانه خودکار تنظیم سند با هوش مصنوعی.

9. **تاریخ:** در صورت وجود فیلد `updatedAt` / `lastUpdated` / `dateModified` فقط برای فایل‌های واقعاً ویرایش‌شده، تاریخ روز را بگذار.

10. **اعتبارسنجی قبل از Push:**
    ```
    npx tsc --noEmit
    npm run lint
    npm run build
    ```
    در صورت خطا، اصلاح کن و دوباره تست کن. سپس فقط فایل‌های این مأموریت را روی شاخه Review پوش کن و SHA + لینک Diff را گزارش بده. Merge نکن.

### اقدامات مجاز (حداقلی و مؤثر)

**در `src/data/samples/leader-office-letter.ts`:**

1. **metaTitle و metaDescription و h1Title** را طوری بازنویسی کن که عبارات پرتکرار زیر به‌صورت طبیعی در آن‌ها بیاید (بدون keyword stuffing):
   - نامه به بیت رهبری
   - متن نامه به رهبری برای کمک مالی
   - شروع نامه به رهبری
   - درخواست عفو (در صورت وجود بخش مرتبط)

2. در `sampleStructureContent` (یا بخش معادل قالب‌های متنی) **حداکثر ۴ الگوی تفکیک‌شده و آماده استفاده** اضافه یا تقویت کن:
   - الگوی ۱: شروع رسمی نامه + متن کامل درخواست کمک مالی / معیشتی / درمان / مسکن
   - الگوی ۲: درخواست عفو یا تخفیف مجازات (ارسال به دفتر رهبری / کمیسیون عفو)
   - الگوی ۳: نامه برای اشتغال یا رفع موانع اداری
   - الگوی ۴: تظلم‌خواهی یا شکایت مردمی به دفتر رهبری

3. یک بخش راهنمای کوتاه و عملی اضافه کن با عنوان تقریبی:
   «چگونه نامه به رهبری بنویسیم و از چه طریقی ارسال کنیم؟»
   (پست، سامانه ارتباطات مردمی، نکات نگارشی رایج — بدون ادعای نتیجه قطعی)

4. در `faqs` حداقل ۳–۵ سؤال پرتکرار مرتبط با کوئری‌های بالا بگنجان (مثلاً نحوه شروع نامه، مدارک پیوست، تفاوت درخواست کمک و درخواست عفو).

**در `src/data/services/leader-office-letter.ts`:**

- متادیتا و توضیحات خدمت را با همان عبارات کلیدی تقویت کن.
- لینک داخلی واضح به صفحه نمونه `/samples/leader-office-letter` بگذار.
- CTA تبدیل به درخواست تنظیم حرفه‌ای را حفظ یا شفاف‌تر کن (بدون اغراق).

**ممنوع:** تغییر اسلاگ، حذف بخش‌های موجود پرکاربرد، بازنویسی کامل صفحه، افزودن امتیاز ساختگی یا نظر جعلی.

**اقدام:** صفحه در حال حاضر جایگاه نسبتاً خوبی دارد. ساختار برنده را حفظ کن. قالب‌ها را برای پوشش فرماندار، استاندار، بخشدار و درخواست کمک/عمرانی تقویت کن. هدف: حفظ یا بهبود تدریجی به سمت رتبه ۱ بدون بازنویسی مخرب.

- درخواست کمک هزینه درمان / جهیزیه

**اقدام:** قالب‌های مجزا برای تحت پوشش کمیته امداد، معرفی‌نامه، بهزیستی (تحت پوشش و کمک)، و درخواست کمک درمان/معیشتی.

**اقدام:** پوشش در صفحات bank موجود؛ لینک‌سازی متقابل بین صفحات بانک.

## بخش سوم: لینک‌سازی داخلی (الزامی و محدود)

- از صفحات این فاز به صفحات مرتبط خوشه وثیقه و اجرای احکام **فقط لینک بده** (مثلاً اگر در متن نامه به موضوع وثیقه یا توقیف اشاره شد).
- از صفحه خدمت به صفحه نمونه متناظر لینک واضح بگذار.
- از ساخت صفحه جدید با نیت یکسان خودداری کن (جلوگیری از cannibalization).

## بخش چهارم: اعتبارسنجی و گزارش

پس از اتمام ویرایش‌ها:

1. تعداد `\u200c` در هر فایل تغییریافته باید `0` باشد.
2. اجرا کن:
   ```
   npx tsc --noEmit
   npm run lint
   npm run build
   ```
3. فقط فایل‌های این مأموریت را stage و commit کن با پیام واضح، مثلاً:
   ```
   seo(phase1): strengthen leader-office and administrative letter samples for GSC queries
   ```
4. روی شاخه Review پوش کن.
5. گزارش بده:
   - نام شاخه
   - SHA کامیت
   - لیست فایل‌های تغییر یافته
   - لینک Diff در GitHub
   - خلاصه تغییرات meta/H1 و تعداد قالب‌های اضافه‌شده
6. **Merge و Deploy انجام نده.** منتظر دستور صریح کاربر بمان.
